# Bedrock Usage Monitoring

## Overview

This document describes how to monitor Amazon Bedrock Claude Opus usage
in this development account.

## A. Live / Near-Real-Time Dashboard

**AWS Console path:**
```
AWS Console → CloudWatch → Dashboards → intelligence-engine-bedrock-usage
```

The dashboard shows:
- **Top row**: single-value widgets for 24h input/output/cache tokens and invocation count
- **Usage over time**: input vs output tokens, cache read/write tokens (5-minute granularity)
- **Daily volume**: hourly stacked token totals
- **Reliability**: client errors, invocation latency (avg + p95), time to first token
- **Model breakdown**: invocations and tokens by all tracked Opus model versions

Metrics typically appear within 1-5 minutes of an invocation.

## B. AWS Generative AI Observability

AWS provides built-in Bedrock observability at:
```
AWS Console → Amazon Bedrock → Observability (left nav)
```

This shows model invocation metrics natively, including per-model breakdowns.
It uses the same underlying CloudWatch metrics as our custom dashboard.

## C. Actual Cost

**AWS Console path:**
```
AWS Console → Billing and Cost Management → Cost Explorer
→ Filter: Service = Amazon Bedrock
```

Cost Explorer data is **delayed 24-48 hours** behind real-time usage.
It shows actual billed amounts, not estimates.

For near-real-time token counting, use the CloudWatch dashboard or CLI script.

## D. Command Line

### Token Usage (Near-Real-Time from CloudWatch)

```bash
# Last 24 hours
python scripts/bedrock_usage.py --profile intelligence-dev --hours 24

# Last 7 days
python scripts/bedrock_usage.py --profile intelligence-dev --days 7
```

### Billed Cost (From AWS Cost Explorer, 24-48h delay)

```bash
python scripts/bedrock_usage.py --profile intelligence-dev --cost --month-to-date
```

## E. What Each Token Metric Means

| Metric | Meaning |
|--------|---------|
| **InputTokenCount** | Tokens in the user/system prompt that are NOT served from cache. Billed at standard input rate. |
| **OutputTokenCount** | Tokens generated by the model in its response. Billed at output rate. |
| **CacheReadInputTokenCount** | Tokens served from Bedrock's prompt cache (not re-processed). Billed at a reduced cache-read rate. |
| **CacheWriteInputTokenCount** | Tokens written into the prompt cache on first use. Billed at a cache-write rate (typically higher than standard input). |

**Important billing note:**
- Total "effective input" = InputTokenCount + CacheReadInputTokenCount + CacheWriteInputTokenCount
- These are billed at *different rates* — you cannot simply add them and multiply by one price
- CacheRead is significantly cheaper than standard Input
- CacheWrite is typically more expensive than standard Input
- Output tokens are billed at their own rate

## F. Privacy — Standard Metrics vs. Detailed Logging

### Standard CloudWatch Bedrock Metrics (Always On)

These are the metrics shown on the dashboard and queried by the usage script:
- Token counts (aggregate per invocation)
- Invocation count
- Latency
- Errors

**These do NOT contain any prompt or response content.** They are safe to
leave enabled permanently.

### Detailed Model Invocation Logging (Optional, OFF by Default)

When enabled, Bedrock writes full request/response payloads to CloudWatch Logs:
- Complete prompts (system + user messages)
- Complete model responses
- Tool definitions and tool call content

**WARNING: DETAILED INVOCATION LOGGING CAPTURES CLAUDE CODE PROMPTS AND RESPONSES.**

This includes everything you type into Claude Code and everything it responds with.

To enable (only when needed for debugging):
```powershell
.\scripts\enable_detailed_bedrock_logging.ps1
```

To disable:
```powershell
.\scripts\disable_detailed_bedrock_logging.ps1
```

Current status: **DISABLED** (not enabled by default).

## H. IAM Principal Attribution

Claude Code invokes Bedrock through the federated identity:
```
arn:aws:sts::{account}:assumed-role/AWSReservedSSO_AdministratorAccess_.../ninad
```

**What this means for cost attribution:**
- CloudWatch metrics provide near-real-time model-level usage (tokens, invocations)
- Cost Explorer provides billed-cost attribution at service level
- For per-request/prompt-level token attribution, detailed invocation logging is required
- IAM principal identity is captured by Bedrock but not exposed in standard CloudWatch metrics

**No IAM Identity Center changes are needed** for the monitoring described here.
