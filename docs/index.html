01 — What it does

Seven phases, five approvals, one briefing

A consultant names a company. The engine verifies it exists before spending tokens, grounds itself in measured workforce data, then reasons through research, analysis, and opportunity identification — pausing for human judgement at every consequential step.

02 — Why it is technically interesting

Six properties most agent demos skip

Durable human-in-the-loop

Execution is segmented: each phase runs to a checkpoint, persists, and its thread ends. Waits hold zero compute and survive restarts and redeploys — proven by killing a live run mid-wait and approving it from a fresh process. The same property at pipeline scale: Step Functions waitForTaskToken suspends for up to 7 days per approval.

Structural client isolation

Every storage and dataset call requires client_id and run_id; S3 keys are built from them. Cross-client reads fail by construction — and tests deliberately attempt them. Prompts are never the security boundary.

Guardrails as configuration

Fourteen rules in YAML — gibberish detection, entity verification before token spend, PII blocking, revision and token ceilings — each with a tunable severity. The engineer console edits and hot-reloads them; blocking happens before inference.

Grounded, not recalled

A hybrid generator (LLM designs each org, Python fills volume deterministically) built 20 synthetic clients; a query layer computes ~30 workforce signals injected into every prompt. The briefing cites measured figures — and an independent Databricks SQL engine reproduces them from the same files.

Enumerated-grant data plane

Five S3 domains with hard IAM walls, including a KMS vault with zero read grants until privacy signoff. Row-level reads are explicit per-stage policies; only the post-QA-gate stage can publish artifacts — the no-bypass gate is an IAM denial, not a convention.

Engineering inside the boundary

An SSM-only workbench (no SSH, no inbound rules, auto-stopping) hosts Claude Code, Terraform, and the Databricks CLI in-account. CI never holds a credential; anything needing AWS runs as in-account golden replay. Secrets live in encrypted SSM, never files.

03 — Cost shape

Built to idle at zero

Twelve stacks; one has a standing cost. Everything else is pay-per-use: tokens, requests, gigabytes, build-minutes. Suspended approvals — application or pipeline — bill nothing.

No NAT gateways, no always-on clusters, no provisioned throughput anywhere. Deleting the one standing-cost stack removes it without touching data.
